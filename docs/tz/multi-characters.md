# Техническое задание: несколько персонажей на аккаунте

## Цель

Пользователь Pocket Spellbook должен вести несколько персонажей на одном аккаунте: создавать, переключать, редактировать и удалять их независимо. Сейчас бэкенд уже хранит несколько персонажей, а клиент показывает только первого из списка.

## Контекст

- Фронтенд: `pocket-spellbook`
- Бэкенд: `pocket-spellbook-server`
- AI-сервис не затрагивается: умный поиск работает по каталогу заклинаний, а не по персонажу.

## Требования к API

1. `GET /characters` возвращает облегчённый список персонажей текущего пользователя:
   - без массива изученных заклинаний;
   - с полем `spellsCount`;
   - сортировка по `updatedAt` по убыванию.
2. `POST /characters` отклоняет создание, если достигнут лимит `MAX_CHARACTERS_PER_USER` (по умолчанию 10), ответом `409 Conflict`.
3. `GET /characters/:id`, обновление, удаление и работа с изученными заклинаниями остаются без изменения контракта.

## Требования к клиенту

1. Страница «Мои персонажи» со списком и формой создания.
2. Карточка конкретного персонажа открывается по маршруту `/character/:id`.
3. Идентификатор активного персонажа сохраняется в `localStorage` и восстанавливается при следующем входе.
4. В навигации есть переключатель активного персонажа, если персонажей больше одного.
5. Каталог заклинаний учит и забывает заклинания только у активного персонажа.
6. При ошибке лимита пользователь видит понятное сообщение.

## Критерии приёмки

- На одном аккаунте можно создать нескольких персонажей и переключаться между ними без выхода.
- Удаление одного персонажа не удаляет остальных.
- Ячейки заклинаний и список изученного хранятся у каждого персонажа отдельно.
- Список персонажей не тащит полный набор заклинаний каждого персонажа.
- При превышении лимита создание не выполняется.

## Вне объёма

- Общий доступ к персонажу между аккаунтами.
- Изменения модели умного поиска.
